## Предлагаемый план, не утверждён

1. Сверить версии и список инструментов работающей установки, воспроизвести
   передачу одной картинки. Проверить, доступна ли она как файл Open WebUI и
   получает ли модель надёжную ссылку на него. Уточнить отдельно созданные
   только внутри песочницы изображения: для них нужен выход из песочницы.
2. Для вставленных в чат картинок добавить передачу из хранилища Open WebUI в
   Jira по ссылке на конкретный файл. Сессию хранить только в контексте запроса;
   скачивать с фиксированного адреса Open WebUI с проверкой доступа, затем
   отправлять в Jira личным токеном. Не разрешать произвольные адреса и переходы
   на другие серверы. Модели передавать описание файла, а не его содержимое.
3. После подтверждения загрузки возвращать фактическое имя вложения и ссылку
   для вставки. Описание обновлять существующим инструментом. Проверить
   преобразование Markdown/wiki, совпадение имён, сохранность остального текста.
   Если описание обновить не удалось, сообщить о загруженном вложении отдельно;
   не выполнять слепые повторы загрузки при неоднозначном сетевом ответе.
4. Проверить на заглушках: точное содержимое, две картинки, одинаковые имена,
   недоступный файл, чужой файл без прав, отсутствие токена, режим чтения,
   превышение лимита, ошибки Jira, параллельные пользователи и частичный успех.
   Затем в согласованной тестовой задаче проверить отображение и полный размер.
5. Обновить README и историю версий, собрать образ, прогнать прежний сквозной
   тест и новые проверки. Публикация — отдельный согласованный шаг.

Предполагаемые затронутые места: server.py, test_e2e.py, README.md, CHANGELOG.md;
при отдельном модуле загрузки — Dockerfile. Фильтр изображений менять только
если проверка покажет, что сведения о выбранном файле не доходят до модели.

Альтернативы: передача содержимого в Base64 проще как низкоуровневое дополнение,
но требует надёжного переноса из песочницы и не должна заставлять модель
переписывать большую строку. Общий каталог не соединяет автоматически файловую
систему браузерной песочницы с сервером и расширяет доступ к файлам.

Не выполнялись: запуск сервисов, реальные сетевые обращения к корпоративным
Jira/Open WebUI, загрузка картинок, изменение производственного кода, тесты.
Неизвестны: фактические версии, лимиты, доступность файла в полном сценарии.
